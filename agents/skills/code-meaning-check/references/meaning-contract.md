# 意味契約

公開契約・ID・派生モデルを変更する前に、値の所有者、導出関係、禁止する状態・遷移を記録し、
人間 owner の承認を得る。

**承認済みの契約はプロジェクト側の設計ドキュメント（チケット、ADR、`docs/` など）に記録する。**
このファイルにはテンプレートと記入例だけを置く。承認記録をここへ蓄積しない。

## テンプレート

- 対象変更:
- 契約の所有者:
- 人間 owner / 承認状態:

| 項目                 | 意味・所有者 | 導出元 | 禁止する入力・状態・遷移 |
| -------------------- | ------------ | ------ | ------------------------ |
| `<公開語彙またはID>` |              |        |                          |

書くときは次の3つを必ず明記する。

- **公開する唯一の値** — 外部へ出すIDや語彙はどれか
- **別レコードへ変換するときだけ作る値** — 導出値。入力として受け取ってはいけない
- **境界で翻訳する語彙** — エラー名・列名・メッセージのうち、利用側の語彙へ写す必要があるもの

## 記入例

2つの実テーブル（工程・品目工程リンク）を1行に結合した読み取り専用の仮想テーブルを追加した例。
**例であって、有効な承認記録ではない。**

- 対象変更: 2テーブルを結合した仮想テーブル `exclusiveProcess` の追加
- 契約の所有者: `exclusiveProcess` の公開API
- 人間 owner / 承認状態: （例のため空欄）

| 項目                                              | 意味・所有者                                   | 導出元                      | 禁止する入力・状態・遷移                               |
| ------------------------------------------------- | ---------------------------------------------- | --------------------------- | ------------------------------------------------------ |
| `exclusiveProcess.publicId`                       | 外部へ公開する唯一の業務ID。仮想テーブルが所有 | 入力（必須）                | 空・未指定は拒否。採番しない。更新では変更不可         |
| `exclusiveProcess.productId`                      | 参照先の品目。リンク側が所有                   | 入力（必須）                | 更新では変更不可                                       |
| `process.publicId`                                | 工程の業務ID。工程が所有                       | `exclusiveProcess.publicId` | 入力として受け取らない                                 |
| `productProcessLink.publicId`                     | リンクの業務ID。リンクが所有                   | `exclusiveProcess.publicId` | 入力として受け取らない                                 |
| `productProcessLink.processId`                    | 工程を指す基底テーブル側FK。リンクが所有       | `exclusiveProcess.publicId` | **仮想テーブルの列として存在しない。入力されたら拒否** |
| `process.isExclusive`                             | 専用／汎用の区別。工程が所有                   | 工程生成時に `true` 固定    | 入力として受け取らない。`false → true` の遷移を禁止    |
| `productionMinQuantity` / `productionMaxQuantity` | 算出値。読み取り専用                           | 他の列から毎回算出          | 入力されたら拒否                                       |

**重要なのは4列目である。** 1〜3列目（項目・意味・導出元）は肯定の定義であり、これだけ並べても
実装は止まらない。`productProcessLink.processId` の行に「**仮想テーブルの列として存在しない**」と
先に書いておけば、その値を入力から読む実装は書かれない。

この行が無かったために、契約外の値をレコード経由で受け渡す実装が生まれ、
**設定する処理・等しいか検証する処理・不一致エラー・その分岐のテスト**が連鎖して増えた。
レビューでは4箇所の別々の「意味の分からない処理」として現れ、1つの設計判断の欠落には見えなかった。

**「何を受け付けないか」を書かない契約は、契約として機能しない。**
